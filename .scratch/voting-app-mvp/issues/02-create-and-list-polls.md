# 02: 투표 만들기와 목록

Spec: [../spec.md](../spec.md)

**What to build:** 운영자가 `/admin`에서 질문 텍스트와 선택지(Option) 2~10개를 입력해 투표(Poll)를 만든다. 선택지 입력칸은 추가하거나 없앨 수 있다. 입력이 잘못되면 무엇이 문제인지 보여주고 입력한 내용은 남긴다. 만든 투표는 홈(`/`) 목록 맨 위에 나오고, `/polls/[id]`에서 질문과 선택지를 만든 순서대로 볼 수 있다. 이 티켓에서는 아직 투표할 수 없다. Drizzle과 Neon 연결, 첫 마이그레이션을 여기서 도입한다.

**Blocked by:** 01 (운영자 로그인과 로그아웃)

**Status:** done

- [x] Drizzle(`drizzle-orm/neon-http`, 이미 설치된 `@neondatabase/serverless`)과 `drizzle-kit`을 설정한다. `DATABASE_URL`을 쓴다
- [x] 스키마: `polls`(id, 질문 텍스트, 생성 시각), `options`(id, poll id cascade, 이름, 순서 번호, (poll id, 이름 소문자) 유일). 투표 id는 추측하기 어려운 형식(UUID 권장)으로 한다
- [x] `drizzle-kit generate`로 만든 마이그레이션 파일을 커밋하고 `drizzle-kit migrate`로 적용한다. 빌드 과정에서는 마이그레이션을 실행하지 않는다. 적용 방법을 README에 적는다
- [x] 투표 규칙 모듈의 입력 검증: 앞뒤 공백 제거, 질문 텍스트 필수, 선택지 2~10개, 빈 선택지 불가, 대소문자를 무시한 중복 불가, 입력 순서 유지. 성공이면 다듬어진 입력을, 실패면 필드별 오류를 돌려준다
- [x] 테스트: 공백 제거와 순서 유지, 선택지 1·2·10·11개, 빈·공백뿐인 질문 텍스트, 빈 선택지, 대소문자·공백만 다른 중복
- [x] 투표 만들기 서버 액션은 액션 안에서 직접 운영자 세션을 검증한다. 투표와 선택지를 함께 저장한다
- [x] 만든 뒤 운영자가 새 투표 링크를 확인할 수 있다
- [x] 홈: 투표 목록을 최신순으로 전부 보여준다(페이지 나누지 않음). 투표가 없으면 "아직 투표가 없습니다"를 보여준다. 각 항목은 `/polls/[id]`로 연결된다
- [x] `/polls/[id]`: 질문 텍스트와 선택지를 순서대로 보여준다. 요청할 때마다 새로 조회한다
- [x] 한국어, Tailwind, 모바일 우선. Create Next App 기본 홈 화면을 교체한다

## Comments

- 2026-09-28 구현 완료. 입력 검증 테스트 12개를 추가해 전체 28개가 통과함. 첫 마이그레이션(`polls`, `options`)을 Neon에 적용함. `next start`로 빈 목록, 검증 오류와 입력값 다시 채우기(JS 없이도), 운영자가 아닌 요청 거부, 생성, 최신순 목록, 투표 페이지, 404를 확인하고 시험용 투표는 삭제함. 대소문자만 다른 중복을 DB 유일 제약이 잡으면 같은 오류 메시지로 바꿔 보여주고, `db.batch`가 원자적으로 롤백되는 것을 실제 DB로 확인함. 새 투표 링크는 `/admin?created=<id>` 배너로 보여줌(복사 버튼 없음).
