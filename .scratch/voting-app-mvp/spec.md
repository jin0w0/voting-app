# Spec: 투표 앱 MVP

Status: ready-for-agent

용어는 [CONTEXT.md](../../CONTEXT.md)를 따른다: **투표(Poll)**, **선택지(Option)**, **표(Vote)**, **결과(Results)**, **투표자(Voter)**, **운영자(Admin)**. 관련 결정: [ADR-0001](../../docs/adr/0001-voters-recognised-per-browser.md), [ADR-0002](../../docs/adr/0002-single-shared-admin-password.md).

## Problem Statement

운영자는 질문 하나를 올려 여러 사람의 선택을 빠르게 모으고 싶다. 하지만 지금은 투표를 만들고 공유하고 결과를 볼 수 있는 곳이 없다. 투표자는 가입이나 로그인 없이 링크 하나로 들어와 선택지 하나를 고르고 결과를 확인하고 싶다. 운영자는 아무나 투표를 만들거나 지우지 못하도록 자기만 관리할 수 있기를 원한다.

## Solution

Vercel에 배포되고 Neon DB에 데이터를 저장하는 한국어 모바일 우선 웹앱을 만든다.

- 누구나 홈에서 투표 목록을 보고, 투표 페이지에 들어가 선택지 하나를 골라 투표할 수 있다. 투표하면 바로 결과(선택지별 표 수, 백분율, 막대, 총 표 수)가 보인다.
- 투표자는 로그인하지 않으며, 브라우저당 투표 하나에 한 표만 던질 수 있다. 표는 바꾸거나 취소할 수 없다.
- 운영자는 공유 비밀번호로 `/admin`에 로그인해 투표를 만들고 삭제한다. 투표는 만든 뒤 수정할 수 없고, 마감 없이 삭제될 때까지 열려 있다.

## User Stories

### 투표자: 투표 찾기

1. 투표자로서, 홈에서 모든 투표 목록을 보고 싶다. 그래야 참여할 투표를 고를 수 있다.
2. 투표자로서, 목록이 최신순으로 정렬되어 있으면 좋겠다. 그래야 새로 올라온 투표를 먼저 볼 수 있다.
3. 투표자로서, 목록에서 각 투표의 질문 텍스트와 총 표 수를 보고 싶다. 그래야 어떤 투표인지, 얼마나 참여했는지 알 수 있다.
4. 투표자로서, 투표가 하나도 없으면 "아직 투표가 없습니다" 안내를 보고 싶다. 그래야 빈 화면이 오류가 아니라는 걸 알 수 있다.
5. 투표자로서, 목록의 투표를 누르면 그 투표 페이지로 가고 싶다. 그래야 바로 투표할 수 있다.
6. 투표자로서, 공유받은 투표 링크로 바로 투표 페이지에 들어가고 싶다. 그래야 목록을 거치지 않아도 된다.
7. 투표자로서, 휴대폰에서도 목록과 투표 화면이 편하게 보이면 좋겠다. 그래야 링크를 받은 자리에서 바로 참여할 수 있다.

### 투표자: 투표하기

8. 투표자로서, 투표 페이지에서 질문 텍스트와 모든 선택지를 만든 순서대로 보고 싶다. 그래야 무엇을 묻는지 알 수 있다.
9. 투표자로서, 선택지 하나를 골라 제출하고 싶다. 그래야 내 의견이 결과에 반영된다.
10. 투표자로서, 선택지를 고르지 않고는 제출할 수 없으면 좋겠다. 그래야 실수로 빈 표를 던지지 않는다.
11. 투표자로서, 가입이나 로그인 없이 투표하고 싶다. 그래야 부담 없이 참여할 수 있다.
12. 투표자로서, 제출하자마자 결과 화면을 보고 싶다. 그래야 다른 사람들의 선택을 바로 알 수 있다.
13. 투표자로서, 이미 투표한 투표 페이지에 다시 들어가면 투표 폼 대신 결과를 보고 싶다. 그래야 내가 이미 참여했다는 걸 알 수 있다.
14. 투표자로서, 같은 브라우저에서는 같은 투표에 두 번 투표할 수 없으면 좋겠다. 그래야 결과가 공정하다.
15. 투표자로서, 버튼을 두 번 누르거나 창 두 개에서 동시에 제출해도 한 표만 기록되면 좋겠다. 그래야 결과가 부풀려지지 않는다.
16. 투표자로서, 투표하지 않은 투표의 결과는 볼 수 없으면 좋겠다. 그래야 대세를 보고 따라가지 않고 내 생각대로 고를 수 있다.
17. 투표자로서, 여러 투표에 각각 한 표씩 던지고 싶다. 그래야 한 투표에 참여했다고 다른 투표가 막히지 않는다.

### 투표자: 결과 보기

18. 투표자로서, 결과 화면에서 선택지별 표 수를 보고 싶다. 그래야 정확한 숫자를 알 수 있다.
19. 투표자로서, 선택지별 백분율과 가로 막대를 보고 싶다. 그래야 비율을 한눈에 비교할 수 있다.
20. 투표자로서, 총 표 수를 보고 싶다. 그래야 몇 명이 참여했는지 알 수 있다.
21. 투표자로서, 결과 화면에서 내가 고른 선택지가 표시되면 좋겠다. 그래야 내 표를 확인할 수 있다.
22. 투표자로서, 페이지를 새로고침하면 최신 결과를 보고 싶다. 그래야 그 사이에 들어온 표도 볼 수 있다.

### 투표자: 예외 상황

23. 투표자로서, 삭제되었거나 없는 투표 링크에 들어가면 "존재하지 않는 투표입니다" 안내를 보고 싶다. 그래야 링크가 잘못됐다는 걸 알 수 있다.
24. 투표자로서, 투표 화면을 연 사이에 투표가 삭제된 뒤 제출하면 같은 안내를 보고 싶다. 그래야 알 수 없는 오류를 보지 않는다.
25. 투표자로서, 투표 제출이 실패하면(네트워크, 서버 오류) 알 수 있으면 좋겠다. 그래야 다시 시도할 수 있다.

### 운영자: 로그인

26. 운영자로서, `/admin/login`에서 비밀번호로 로그인하고 싶다. 그래야 투표를 관리할 수 있다.
27. 운영자로서, 비밀번호가 틀리면 오류 메시지를 보고 싶다. 그래야 다시 입력할 수 있다.
28. 운영자로서, 로그인하지 않고 `/admin`에 들어가면 로그인 페이지로 이동되면 좋겠다. 그래야 다른 사람이 관리 화면에 들어오지 못한다.
29. 운영자로서, 한 번 로그인하면 7일 동안 다시 로그인하지 않아도 되면 좋겠다. 그래야 매번 비밀번호를 입력하지 않는다.
30. 운영자로서, 7일이 지나면 다시 로그인하라고 요구받고 싶다. 그래야 잃어버린 기기에서 영원히 로그인된 채로 남지 않는다.
31. 운영자로서, 로그아웃 버튼으로 바로 로그아웃하고 싶다. 그래야 공용 기기에서 안전하게 나갈 수 있다.
32. 운영자로서, 이미 로그인한 상태로 로그인 페이지에 가면 `/admin`으로 이동되면 좋겠다. 그래야 헷갈리지 않는다.
33. 운영자로서, 일반 화면에는 운영자 버튼이나 링크가 보이지 않으면 좋겠다. 그래야 투표자에게 관리 기능이 노출되지 않는다.
34. 운영자로서, 비밀번호와 세션 서명 키를 바꾸면 기존 로그인이 모두 끊기면 좋겠다. 그래야 비밀번호가 새어 나갔을 때 대응할 수 있다.

### 운영자: 투표 만들기

35. 운영자로서, `/admin`에서 질문 텍스트와 선택지를 입력해 투표를 만들고 싶다. 그래야 사람들에게 물어볼 수 있다.
36. 운영자로서, 선택지 입력칸을 추가하거나 없애고 싶다. 그래야 필요한 만큼 선택지를 둘 수 있다.
37. 운영자로서, 선택지가 2개보다 적거나 10개보다 많으면 만들 수 없으면 좋겠다. 그래야 의미 있는 투표만 생긴다.
38. 운영자로서, 질문 텍스트가 비었거나 공백뿐이면 만들 수 없으면 좋겠다. 그래야 빈 투표가 생기지 않는다.
39. 운영자로서, 비어 있거나 공백뿐인 선택지가 있으면 만들 수 없으면 좋겠다. 그래야 빈 선택지가 보이지 않는다.
40. 운영자로서, 같은 이름의 선택지가 있으면(앞뒤 공백 제거, 대소문자 무시) 만들 수 없으면 좋겠다. 그래야 표가 두 선택지로 갈라지지 않는다.
41. 운영자로서, 입력이 잘못되면 무엇이 문제인지 알려주고 입력한 내용은 남아 있으면 좋겠다. 그래야 처음부터 다시 쓰지 않는다.
42. 운영자로서, 질문 텍스트와 선택지의 앞뒤 공백이 자동으로 잘리면 좋겠다. 그래야 깔끔하게 보인다.
43. 운영자로서, 투표를 만든 뒤 그 투표 링크를 바로 확인하고 싶다. 그래야 곧바로 공유할 수 있다.
44. 운영자로서, 새 투표가 바로 홈 목록 맨 위에 보이면 좋겠다. 그래야 투표자가 찾을 수 있다.

### 운영자: 관리와 삭제

45. 운영자로서, `/admin`에서 모든 투표 목록을 최신순으로 보고 싶다. 그래야 관리할 투표를 찾을 수 있다.
46. 운영자로서, 내가 투표하지 않았어도 모든 투표의 결과를 보고 싶다. 그래야 진행 상황을 확인할 수 있다.
47. 운영자로서, 투표를 삭제하고 싶다. 그래야 잘못 만들었거나 끝난 투표를 치울 수 있다.
48. 운영자로서, 삭제 전에 확인 창을 보고 싶다. 그래야 실수로 지우지 않는다.
49. 운영자로서, 투표를 삭제하면 그 투표의 선택지와 표도 모두 사라지면 좋겠다. 그래야 남은 데이터가 없다.
50. 운영자로서, 삭제된 투표가 홈 목록과 관리 목록에서 바로 사라지면 좋겠다. 그래야 투표자가 없는 투표에 들어가지 않는다.
51. 운영자로서, 투표를 잘못 만들었으면 삭제하고 다시 만들면 된다는 걸 알고 싶다(수정 기능 없음). 그래야 결과가 왜곡될 일이 없다.
52. 운영자로서, 일반 투표자처럼 투표 페이지에서 투표할 수도 있으면 좋겠다. 그래야 따로 시험용 브라우저가 필요 없다.

### 배포

53. 운영자로서, GitHub에 push하면 Vercel에 자동 배포되면 좋겠다. 그래야 따로 배포 작업을 하지 않아도 된다.
54. 운영자로서, `DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET` 환경변수만 설정하면 앱이 동작하면 좋겠다. 그래야 설정이 단순하다.
55. 운영자로서, DB 스키마 변경을 로컬에서 직접 적용하고 그 이력이 저장소에 남으면 좋겠다. 그래야 배포가 DB를 예기치 않게 바꾸지 않는다.

## Implementation Decisions

### 모듈

- **투표 규칙 모듈** (순수, 외부 의존 없음). 테스트 경계 1.
  - 투표 입력 검증: 원시 입력(질문 텍스트, 선택지 문자열 목록)을 받아 성공(다듬어진 질문 텍스트와 선택지 목록) 또는 실패(필드별 오류 목록)를 돌려준다. 규칙은 다음과 같다.
    - 앞뒤 공백을 제거한 뒤 질문 텍스트가 비어 있으면 안 된다.
    - 선택지는 2~10개여야 하고, 비어 있으면 안 되며, 대소문자를 무시하고 비교해 중복이 없어야 한다.
    - 선택지 순서는 입력 순서를 유지한다.
  - 결과 계산: 선택지별 표 수 목록(입력 순서)을 받아 선택지별 표 수와 백분율, 총 표 수를 돌려준다. 총 표 수가 0이면 모든 백분율은 0이다. 백분율은 표시용으로 반올림한다. 합계가 정확히 100이 되도록 맞추지는 않는다.
- **운영자 인증 모듈** (비밀 값과 현재 시각을 인자로 받음). 테스트 경계 2.
  - 비밀번호 확인: 입력값과 설정된 비밀번호를 받아 참/거짓을 돌려준다. 길이가 달라도 타이밍 정보가 새지 않게 비교한다(예: 양쪽을 해시한 뒤 상수 시간 비교).
  - 세션 발급: 서명 키와 현재 시각을 받아 만료 시각(발급 후 7일)이 담긴 서명 토큰을 만든다. Node 내장 암호 기능(HMAC-SHA256)을 쓰고 외부 라이브러리는 쓰지 않는다.
  - 세션 검증: 토큰과 서명 키, 현재 시각을 받아 유효 여부를 돌려준다. 서명이 틀렸거나, 형식이 깨졌거나, 만료된 토큰은 거부한다.
- **DB 층** (Drizzle, `drizzle-orm/neon-http` 드라이버, 이미 설치된 `@neondatabase/serverless` 사용). 투표 목록(총 표 수 포함), 투표 하나와 선택지 조회, 투표자의 기존 표 조회, 표 기록, 투표 만들기(투표와 선택지를 함께), 투표 삭제를 제공하는 얇은 함수들이다.
- **서버 액션**: 투표하기, 투표 만들기, 투표 삭제, 로그인, 로그아웃. 각 액션은 위 모듈과 DB 층을 호출하고 쿠키를 읽고 쓰는 얇은 층이다. 투표 만들기와 투표 삭제 액션은 페이지 보호와 별개로 액션 안에서 직접 운영자 세션을 검증한다.
- **페이지**: `/`(목록), `/polls/[id]`(투표 폼 또는 결과), `/admin/login`, `/admin`(만들기 폼과 목록). 이 Next.js 버전에서는 `params`와 `cookies()`가 비동기이고, `middleware` 대신 `proxy` 규칙을 쓴다. `/admin` 보호에 proxy를 쓸지, 페이지와 레이아웃에서 세션을 확인할지는 구현자가 정한다. 단 서버 액션 안의 검증은 반드시 둔다.

### 스키마

- `polls`: id, 질문 텍스트, 생성 시각
- `options`: id, poll id(삭제 시 cascade), 이름, 순서 번호. (poll id, 이름 소문자)에 유일 제약
- `votes`: id, poll id(삭제 시 cascade), option id(삭제 시 cascade), 투표자 ID, 생성 시각. **(poll id, 투표자 ID)에 유일 제약**을 두어 브라우저당 1표를 DB가 보장한다.
- 표를 기록할 때는 그 option이 해당 poll에 속하는지 확인한다. 유일 제약 위반은 "이미 투표함"으로 처리하고 결과 화면을 보여준다.
- id 형식(정수 또는 UUID)은 구현자가 정한다. 투표 링크에 쓰이므로 추측하기 어려운 UUID가 좋다.

### 쿠키와 세션

- **투표자 쿠키**: 처음 투표할 때 발급하는 무작위 익명 ID. httpOnly, 1년 유지, 서명하지 않는다(ADR-0001). 쿠키가 없는 방문자는 아직 투표하지 않은 것으로 본다.
- **운영자 세션 쿠키**: 운영자 인증 모듈이 만든 서명 토큰. httpOnly, Secure(운영 환경), SameSite=Lax, 7일 유지. 로그아웃하면 지운다(ADR-0002).
- 무차별 대입 방지는 따로 두지 않는다. 긴 비밀번호와 타이밍 안전 비교에 의존한다.

### 결과 공개

- `/polls/[id]`는 서버에서 판단한다. 투표자 쿠키로 기존 표가 있으면 결과를 보여주고(내가 고른 선택지 표시), 없으면 투표 폼을 보여준다. 결과 데이터는 투표하지 않은 투표자에게 절대 보내지 않는다.
- 운영자 세션이 유효하면 `/admin`에서 각 투표의 결과를 볼 수 있다.
- 실시간 갱신은 없다. 요청할 때마다 새로 조회한다(캐시된 정적 페이지 금지).

### 환경변수와 배포

- 환경변수: `DATABASE_URL`(이미 `.env.local`에 있음), `ADMIN_PASSWORD`, `SESSION_SECRET`. 로컬과 운영이 Neon DB 하나를 같이 쓴다.
- 마이그레이션: `drizzle-kit generate`로 SQL 파일을 만들어 커밋하고, 로컬에서 직접 `drizzle-kit migrate`로 적용한다. 빌드 과정에서는 마이그레이션을 실행하지 않는다.
- GitHub 저장소를 Vercel에 연결해 push할 때 자동 배포한다. 원격 저장소 생성과 Vercel 연결은 사람이 한다.
- UI는 한국어만 쓰고, Tailwind(이미 설치됨)로 모바일 우선 스타일을 적용한다. Create Next App 기본 홈 화면은 교체한다.

## Testing Decisions

- 좋은 테스트는 모듈의 공개 인터페이스에 입력을 넣고 출력만 확인한다. 내부 헬퍼, 해시 방식, 토큰 내부 형식 같은 구현 세부는 확인하지 않는다. 토큰은 "발급한 것이 검증을 통과한다", "변조되면 실패한다", "7일 뒤에는 실패한다"처럼 동작으로만 확인한다.
- 테스트 도구는 Vitest를 새로 추가하고 `test` 스크립트를 등록한다.
- 테스트 대상:
  - **투표 규칙 모듈**
    - 유효한 입력의 공백 제거와 순서 유지
    - 선택지 1개, 2개, 10개, 11개
    - 빈 질문 텍스트, 공백뿐인 질문 텍스트
    - 빈 선택지
    - 대소문자만 다른 중복, 공백만 다른 중복
    - 총 표 수 0일 때의 백분율
    - 한 선택지만 표를 받은 경우
    - 반올림이 필요한 경우(예: 1/3)
  - **운영자 인증 모듈**
    - 맞는 비밀번호, 틀린 비밀번호, 길이가 다른 비밀번호
    - 발급 직후 세션 검증 통과
    - 7일 직전 통과, 7일 이후 거부
    - 다른 서명 키로 검증하면 거부
    - 변조된 토큰, 형식이 깨진 토큰 거부
- 테스트하지 않는 것: DB 층, 서버 액션, 페이지, 쿠키 입출력. 브라우저당 1표는 DB 유일 제약이 보장한다.
- 선행 사례: 코드베이스에 기존 테스트가 없다. 이 두 모듈의 테스트가 첫 사례가 된다.

## Out of Scope

- 투표자 로그인, IP 기반 제한, 쿠키 삭제나 시크릿 창을 이용한 재투표 차단
- 투표 수정, 마감(수동이든 시각 지정이든), 표 변경이나 취소
- 여러 운영자 계정, 운영자별 권한, 비밀번호 재설정, 로그인 시도 횟수 제한
- 실시간 결과 갱신(폴링, 웹소켓)
- 복수 선택, 순위 투표, 선택지 이미지
- 목록 페이지 나누기, 검색, 정렬 옵션
- 한국어 외 언어
- 개발용과 운영용 DB 분리, 빌드 과정의 자동 마이그레이션
- DB 층과 화면에 대한 통합 테스트나 E2E 테스트
